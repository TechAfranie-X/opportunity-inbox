# Holdout v1 protocol (independent reader evaluation)

- **What it is:** 123 real messages drawn (seeded, stratified, hash in `docs/holdout-draw.sha256`) from stored mail excluding all 91 development-set messages. The draw hash was committed BEFORE either semantic reader ran on it.
- **What the evaluator gets:** only `~/.opportunity-inbox-validation/holdout-v1/evaluator-package/` (`review.html` + `README.txt`): Gmail links and blank label fields. No product answer, model answer, stratum or draw file is in the package. The readers' predictions are stored apart, in `~/.opportunity-inbox-sealed/holdout-readings.json`.
- **No tuning:** nothing in the reader, the investigator or the product may be tuned on these messages before the initial independent assessment. The only allowed use before then is the provisional diagnostic printed by `scripts/holdout-score.ts` without `--labels` (person corrections and deterministic facts, labelled NOT independent), and it must not drive changes.
- **Initial assessment:** `node ... scripts/holdout-score.ts <sub> --labels holdout-labels.json` (it refuses labels made for a different draw). The first run with labels writes `.assessed`; later runs print that the holdout is now development data. The promotion rule for `READER_INPUT=parts` is printed by the tool: >= 100 independent labels, B no worse than A on FALSE OFFERS and FALSE TERMINAL outcomes, B ahead by at least 5 correct.
- **Afterwards:** record the initial result in the handoff, then treat the holdout as development data and draw a new one (`scripts/holdout-draw.ts --seed holdout-2`) for the next claim.
